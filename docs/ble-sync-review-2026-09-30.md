# BLE 읽기 위치 동기화 점검 — 2026-09-30

## 판정과 적용 범위

의도는 유지된다: 한 번 명시적으로 페어링한 리더와 계정·Wi-Fi 없이 읽기 위치만
교환하고, 실제 페이지 이동은 사용자 확인을 받는다. 다만 기존 BLE 작업은
최신 main에 없었고, 과거 X3 테스트도 광고까지만 확인했다. 자동 동기화가 실제
완료된 것으로 볼 수 없었다.

이번 후보는 펌웨어 main `ee188fe7`(CrossPoint 1.6.5, FreeInk SDK `111fdcc7`)에
`feat/ble-reading-sync`의 `68a77147`을 통합하고, 앱 main `c22df41`에 앱 BLE
`e4751d3`을 통합한다. 양쪽 작업 브랜치는 `codex/ble-sync-review`다.
이 문서는 통합 변경의 리뷰와 로컬 검증 기록이다. main 병합·게시 여부와
배포 바이너리의 정확한 식별자는 GitHub PR·릴리스 기록으로 확인한다.
기존 `v1.7.0-beta.4` 배포에는 이 후보가 들어 있지 않다.

| 최종 오퍼 저장 | 첫 OFFER 이후 메모리가 줄어도 JSON·SD 작업 진입 | 최종 W에서도 24/8 KiB 재검사; 부족하면 NO_MEMORY, 위치 미저장 |
| 시작 중 종료 | 시작 worker가 멎으면 runtime을 버리고 라디오가 꺼졌다고 처리 | 최대 15초 대기 후 복구 재시작; 살아 있는 worker를 해제하거나 Wi-Fi에 넘기지 않음 |
| 시작 직후 연결 | init 중 연결 상태를 초기화하거나 이미 종료한 세대로 취급 | 광고 전에 상태 초기화; 시작 중 연결에도 5초 인증 유예 적용 |
| 종료 실패 | NimBLE deinit 실패를 로그만 남기고 Wi-Fi로 진행할 수 있음 | 종료 실패 시 breadcrumb를 남기고 복구 재시작 |
| 연결 통계 | connect/disconnect 세대를 연결 수로 집계; init 중 연결 누락 | 실제 connect 콜백만 별도 집계, 해제는 세대 무효화에만 반영 |
| 개인정보 | reading-sync.log에 리더·주변기기 ID와 원시 상태 기록 | 단계·건수 중심으로 축소 |
| 계약 | HTTP/BLE 위치 정책이 달라질 위험 | 같은 ReadingExchange/ReadingSync 병합·저장 사용; BLE 목록에서 경로 제외 |

콜백은 고정 크기 4-record 큐에 복사만 하고 JSON/SD 처리는 소유 루프에서 한다.
본딩·암호화·인증된 연결만 명령을 받으며, 자동 창에서는 새 페어링과 START_AP를
거부한다. 이 보안 경계의 소스 검토와 호스트 테스트는 실제 무선 인증 검증을 대신하지 않는다.

## 남은 기능상 제약

- 96 KiB 시작 기준은 과거 83 KB Home 사례를 의도적으로 건너뛴다. 따라서 안전하게
  차단되는 것과 원하는 자동 동기화가 제공되는 것은 별도 판정이다. 새 SDK에서 X3/X4를
  측정하고, 부족하면 유휴 화면 자원 수명을 줄이는 후속 작업이 필요하다. 기준을 낮춰
  광고만 성공시키는 방식은 수용하지 않는다.
- iOS 백그라운드 실행·상태 복원은 운영체제가 결정한다. 모든 창에서 즉시 전달되거나
  사용자가 앱을 강제 종료해도 복구된다는 보장은 없다. macOS는 앱 실행 중에만 대기한다.
- Home의 “Synced with iPhone” 상태 표시는 이번 범위에 구현되지 않았다.
- heap 기준은 임시 안전 예산이다. 실제 연결·알림·JSON·SD 처리의 최저값 및 해제 후
  회복값이 X3/X4에서 확인되기 전에는 성능·안정성 또는 배포 승인을 주장하지 않는다.

회귀 테스트는 END-before-write-ACK, 확인되지 않은 오퍼의 성공 집계 방지,
데모 시작 전 차단, HTTP 작업/취소 정리 중 BLE 중단, 최종 W 전 힙 감소,
과거 저메모리 Home 차단과 최대 블록 감소를 포함한다. 최종 리뷰에서 추가한
4개 테스트는 시작 중 연결의 인증 유예, 재연결별 유예, millis 순환과
연결/해제 콜백의 연결 수 집계를 검증한다.
앱 테스트 빌드에는 기존 URLProtocol Sendable/AppIntents 경고가 남아 있다.
펌웨어 호스트 빌드의 기존 테스트 stub 관련 경고와 실제 펌웨어 빌드 결과도 구분한다.

최종 리뷰 수정 전 테스트 이미지(작업 트리 상태; 배포 산출물이 아님):

| 환경 | 크기 | SHA-256 |
| --- | ---: | --- |
| default (`ee188fe7-w52ca1776`) | 6,420,512 B | `1c6e0ddda1f6cb5e7f4e2eb31c951a2502c69d990f62afbdbc0f83497af6c3ce` |
| gh_release | 6,363,712 B | `ce7bb60b3ba1f553121d607a48400b35dfc714776763d679537bbc8786733334` |

산출물은 매 빌드에서 바뀌므로 설치 전 `firmware/LATEST_BUILD.txt`를 확인한다.
실기 설치는 확인하지 않았다. 수정 전 default flash 사용률 97.8%, gh_release 96.9%로 추가 기능의 공간
예산이 작다. 정적 RAM 사용률 약 21.3%는 런타임 힙 여유의 증거가 아니다.
FreeInk SDK 작업 트리의 8줄 SD 메타데이터 패치는 기존
`scripts/patch_storage_sdk.py`가 재현하며, SDK 포인터를 변경한 것이 아니다.


## X3/X4 실기 인수 절차

두 장치 각각 펌웨어의 테스트 커밋/작업 트리 fingerprint와 이미지 SHA-256, 앱 빌드를
함께 적는다. 사용자가 File Transfer → Join a Network 경로로 후보를 설치한 뒤 실행한다.
설치 전 원본은 `firmware/LATEST_BUILD.txt`로 확인하고, 이 문서를 통과 기록으로 대신하지 않는다.

1. Continue Reading에서 최초 페어링만 수행한다. 핫스팟으로 바꾸지 않아도 리더가 기억되는지,
   재실행 후 다시 페어링하지 않는지 확인한다. 미페어링·데모·설정 OFF에서는 자동 연결이 없어야 한다.
2. 책 닫기→Home, 책 닫기→Library, 스택 복귀, 다이얼로그에서 Home 복귀, wake, 수동/자동 sleep을
   각각 검사한다. 실제 `lists`와 `offers` 완료 수를 확인한다. `opened` 증가만으로 성공 처리하지 않는다.
3. iPhone 앞/배경/잠금 상태, 범위 이탈 후 재진입, Bluetooth OFF/ON, 앱 재시작을 검사한다.
   여러 번 반복한 후 수동 Nearby Sync와 Wi-Fi 전환이 자동 연결에 방해받지 않아야 한다.
4. 페어링되지 않은 다른 폰을 접근시켜 패스키 표시·본딩 추가·위치 쓰기가 불가능한지 확인한다.
   기존 폰의 회전하는 비공개 주소(RPA) 재접속도 확인한다.
5. Home에서 창이 시작되는 동안 즉시 책 열기/Back/Sync를 반복한다. 시작 중 종료·시간 초과 후
   두 라디오가 함께 살아 있거나 멈추지 않아야 한다. sleep 창을 마치면 실제 deep sleep과 다음 wake가 된다.
6. Same Wi-Fi로 돌아와 `/api/status.readSync`의 시작/준비/최저/종료 free heap·largest block,
   gate/close 이유, lists/offers를 수집한다. 읽기 시 50 KiB 이상과 누수 없음, BLE 최소 20 KiB,
   종료 후 Wi-Fi/HTTP에 필요한 연속 블록 회복을 별도로 판정한다. 네 방향 화면도 확인한다.
7. 앱→리더와 리더→앱 위치를 실제 같은 글자에서 비교한다. 제안 거절 시 현재 페이지 유지,
   수락 시 목표 글자로 이동, 재열기 후 위치 유지, SD 쓰기 실패/메모리 부족 시 성공 표시 없음도 확인한다.

| 장치 | 테스트 커밋/fingerprint + 이미지 SHA-256 + 앱 빌드 | 실제 교환·힙·sleep·인증 결과 |
| --- | --- | --- |
| X3 | 미실시 | 대기 |
| X4 | 미실시 | 대기 |

출시 판단은 `release-checklist.md`와 위 실기 결과를 함께 사용한다.
